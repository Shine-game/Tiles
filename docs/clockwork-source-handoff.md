# CODEX integration — Clockwork Workshop v1.0.0

## Scope and authority
Implement visual theme *only* in existing Godot 4.x puzzle. Preserve board dimensions (9×9, 11×11), legal placement, score, symmetry, helper inventories, UI behavior and input mapping. Use `runtime/theme.json` as the **single authoritative current asset/geometry contract**. This document expands that JSON, not a competing manifest. P01/P02 earlier standalone handoffs refer to superseded 196/204 px lower gears and 120 px hatch; do not reintroduce those values. These exported assets have NOT been tested in Godot/Android.

## Imports / pivots
Use lossless textures, straight alpha, linear filter, no repeat and no mipmaps unless device checks justify a change. All P01 C/T images are 256×256 and centered around `(128,128)`; all P02 L/H/J images are 512×512 and centered at `(256,256)`. An ordinary sprite is drawn with `Sprite2D.centered = true` at a cell-center at scale `cell_ui_size/256`. A landmark is at the common 2×2 corner (top-left support +1,+1 cells), at the **same** scale `cell_ui_size/256`. `CH01_link.png` is 64×64; nominal painted link ~54×24 px, anchor pair x≈17/46 and y=32. Textures retain generous transparent margins deliberately. Do not crop at runtime without adjusting origins.

## P01 ordinary networks — 6 parts per logical color
Order: east/source half-arm T01 (rotate 90° per N/E/S/W), C01 stationary ring, T02 near-socket collar, C02 wheel, stationary C03 center pin; one T03 shared coupling **per unordered neighboring same-color cell pair** drawn at the shared edge center. T01 arm runs center `(128,128)` to east boundary `(256,128)` in its source canvas. Socket Ø180, wheel Ø160, tube Ø130. Existing cores stay intact when topology gains arms; only new arms/collars/couplings are added. Core remains still until a valid same-color 2×2 activates it.

## P02 landmarks — 4-layer assembly, one per same-color 2×2
An eligible landmark is detected from ANY four same-color occupied 2×2 cells, regardless of placement history. Pivot at shared cell corner; supports may overlap. Core axes relative to 512 landmark canvas: `(128,128),(384,128),(128,384),(384,384)` around landmark center `(256,256)`.
1. 0.00–0.40 s: four core wheels rise *above* their 180 px stationary socket rings (unchanged sprites); L01 Ø224 central gear rises between them onto the same operating plane.
2. 0.40–0.85 s: four cores start counterclockwise, L01 clockwise. Keep all gears visible for a deliberate engagement interval.
3. 0.85–1.20 s: L02 centered axle telescopes up; use depth/shadow cues, **no lateral shift**.
4. 1.20–1.70 s: L03 Ø236 open ornate gear seats, spinning clockwise, angularly locked to L01.
5. 1.70–1.95 s: 60px H00 hatch closes at top. Later it may split/slide apart using provided H00 halves.
The older P02 L04 Ø120 hatch has intentionally been superseded and is **not present** in the consolidated runtime sprites.

**Mechanical caveat**: at axis separation `sqrt(128²+128²)=181.019px`, fixed 160px cores and 224px central have **10.981px of tooth-tip circle overlap**. This allows visible interlacing but does not establish real involute teeth or safe phases. Verify by rotating through a full cycle, and record any collisions. Approximate speed ratio central/core =224/160=1.4; use actual teeth/pitch circles for exact meshing if validated. Existing participating cores must never be instantiated or phase-reset twice, including 3×3 or denser overlapped landmark arrangements.

## P03 chains
Only make one chain per sorted pair of neighboring same-color landmark origins differing by `(±1,0)` or `(0,±1)`. Landmarks are 256 source px apart. Place two taut runs with centerlines at 28 px either side of the central connecting axis; 24px thick. `CH01_link.png` repeats every **29px** using the link's anchor spacing. Top run assembles **from left axle to right axle**, bottom run simultaneously **from right to left**, independently adding individual links (never four midpoint-converging fronts). Total 0.35–0.50 s after both landmarks mechanically ready. When complete, move link positions continuously in the same directions, cropping or hiding returns under junctions. For vertical chains rotate *the complete pair* 90°: do not invent a competing up/down direction policy. Use the same shared clock and adequate run-end clipping. No sag and no auxiliary tensioning wheels.

## P04 terminals, return housings, steam
A 90px J00 housing *below* the cap conceals chain returns/intersections. A 60px visible cover *above* it preserves visibility of the 224/236px lower mechanisms. `H00_plain_hatch`, `H01_valve`, `H02_rotating`, `H03_exhaust` exist for both colors. Choose a terminal deterministically per landmark (e.g. hash of top-left board coordinate and seed), with H00 as initial default until feature stage. Valve stationary; decorative wheel rotates slowly on separate pivot; exhaust stationary grille with optional H03 left/right shutter parts sliding sideward over opaque H03 underlay. Steam sprites `artwork/ground/steam_{0..2}.png` are translucent puffs; do not obscure the puzzle. For future tier extension, move the H00 split halves outward to allow L02 to extend. **Neither shutters nor the future axle extension are implemented animation clips in this asset package**; these are separate sprites and Codex needs to implement the transforms.

**Chain crossing abstraction:** A single 90px solid junction masks overlapping horizontal and vertical chain returns. This is an intentional visual simplification, not an engineered multi-sprocket transmission; it should not be described as a physically exact four-chain junction.

## P05 environment
Use one continuous portrait paper source `background/drafting_paper_1080x1650.png` below all board content; letterbox/crop for device UI without changing the board input mapping. `ground/plate_01/02.png` are **opaque, face-only, edge-matched 256×256 textures** with identical border colors across variants and quarter turns; select variant/rotation deterministically per board coordinate, stable across later placements. They do not include outlines, extrusions or pins. Render occupied region as fused material: no internal sidewalls, including along mixed-color occupied neighbors. Exposed contour uses separate `sidewall_4ui.png` and `edge_lip_2ui.png`: apply exact **4 UI/display pixels** thickness, not 4 source px, on visible lower/exposed boundaries via an occupancy-driven boundary renderer, with holes and concave corners covered. The small 48×48 transparent pins are separate from frame pins. Draw one pin per eligible exposed *perimeter* corner, not every internal junction; select color from the supporting logical cell. If multiple differently colored incident cells meet at one eligible corner, use the deterministic smallest `(row,column)` occupied perimeter support; this is an implementation tie-break, not a gameplay change.

`artwork/frame.png` is 256×266 RGBA, 256-square top face, 228×228 *fully transparent* opening at `(14,14)` and 10px lower sidewall. Use one Godot `NinePatchRect`: `draw_center=false`, `patch_margin_left/top/right=14`, `patch_margin_bottom=24`, `axis_stretch_horizontal/vertical=STRETCH`, `mouse_filter=IGNORE`. At scale(1,1): `frame.position=board_rect.position-Vector2(14,14)` and `frame.size=board_rect.size+Vector2(28,38)`. Fitting a board+frame into a slot uses `side=min(available_rect.size.x-28, available_rect.size.y-38)`; frame takes `(side+28,side+38)` and board is inset `(14,14)`. Do not rescale frame node uniformly or apply a second 10px extrusion. Check wood grain under nine-slice stretching at game scale.

## P06 reveals, stable state, lifecycle
P01 T01 canonical east mask `masks/T01_from_core_E.png`; N/S/W masks provided as well. `masks/T01_from_edge_*.png` are reverse directional fields, and the two-front shader `shaders/directional_reveal.gdshader` supports simultaneous entry from core or edge via a shared CPU visual clock. Mask values 0→1 represent arrival along path, **not transparency**; artwork alpha supplies silhouette. C01/C02/L01/L03 are vertical emergence: seat and shadow depth rather than scaling flat gear in X/Y; cannot fake their emergence with horizontal wipes. T02/T03 collars lock into place independently. The existing clock continues through additional logical placements; do not speed-finish older growth when a new placement arrives. No external same-color source: all new cells of each source-free connected component form their buds simultaneously. Valid additions to existing cells never replay their old components.

Use stable keys: core = cell coordinate+color+part, arms = cell+direction, couplings = sorted cell pair, landmark = top-left support+color, chains = sorted landmark pair. Completed components remain. Undo: selectively retract/remove only unsupported parts, including short descending mechanic; surviving gear motion never resets. Load/switch theme: derive completed graphical state from logical board **without replaying construction**. Reset: discard nodes/schedules and return to game's authoritative starting board. Invalidate stale callbacks with a revision/generation key. The game owns legal placement, scoring, symmetry, button animation gates and pause policy.

## Implementation / validation checklist
- Import each path listed by `theme.json`; validate no missing textures.
- Check core/line masks in all 16 N/E/S/W topologies, both logical colors, including diagonal-only and mixed-color adjacency.
- Check T03 boundary coupling appears once; confirm line segments attach without caps floating into empty cells.
- Test P02 same-color 2×2 across multiple turns, 3×2/2×3 (2 landmarks), 3×3 (4) and 4×4 (9), with physically compatible gear phases and no restarted shared wheel.
- Chains: 3×2 has 1 join, 3×3 has 4, 4×4 has 12; confirm no diagonal or cross-color links. Check horizontal/vertical circulation and cap crossing at 4-way chain centers.
- Check steam vent remains opaque under shutters; hatch halves open only when extending next stage.
- Test 9×9 and 11×11 on an actual Android device and verify performance and phone-scale legibility.
- Verify frame hit-testing and no clipping at corners or lower 10px sidewall.

Not validated in this export: live Godot/Android behavior, exact involute gear mesh, actual nested mechanical rising, animated vent shutters/steam timing, and chain linking state machine. These are implementation/testing responsibilities, not completed tasks.
